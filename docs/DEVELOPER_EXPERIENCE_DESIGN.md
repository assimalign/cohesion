## 1. Mental model and the differentiator

**Every deployable thing is an ordinary .NET project that picks a Cohesion SDK; every relationship is an ordinary project or package reference.** A resource project (`Sdk.Web`, `Sdk.Database`, …) is a `Program.cs` executable — top-level statements composing the area's application through the area builder, exactly like any .NET exe — that builds to a runnable host (the area's `Host<TContext>` subclass). Orchestration is **opt-in**: with `<CohesionApplicationModel>enabled</CohesionApplicationModel>` in its csproj the SDK also derives a **manifest** at build time, generates the typed `Resource` accessors and registers the area's default control plane; a project that leaves it disabled is a plain exe. A gateway project (`Sdk.Gateway`, always enabled) references resource projects (same repo), manifest packages (other repos) or running resources (other clusters) and realizes the graph on one process, N processes, Docker, Kubernetes or several clusters. Customer code is identical across all of them.

## 3. Resolution of the tensions

**T1 — `<Area>.Application` (survived, mechanics corrected).** The customer's `Sdk.<Area>` project is the resource instance and an **ordinary executable**: `Program.cs` (top-level statements) composing the area's application through the area builder — `WebApplication.CreateBuilder(args)` … `await app.RunAsync();` — exactly like any .NET exe, and nothing else is required (R4; this is what "every resource is an executable", R3, means on disk). Manifest generation is `Sdk.<Area>` **at build** (`CohesionCreateResourceManifest`, `BeforeTargets=CoreCompile`, no compile; MSBuild evaluation is declarative, so the 2026-07-13 directive's "build tasks code-generate" is honored literally) and runs **only when the project opts in** with `<CohesionApplicationModel>enabled</CohesionApplicationModel>`, generating `resource.json`, `Resource.g.cs` (typed accessors over the ambient `ResourceContext`) and `ResourceControlPlane.g.cs` (registration with the area's default control plane); `<Area>.ApplicationModel` is the declarative plane and delivers that default control plane — every resource of one type exposes the same one, which is why each resource type owns its `<Area>.ApplicationModel`; the framework-owned `.Application` name is retired. *Scope narrowed (R4):* orchestration semantics are **opt-in per project** — `CohesionApplicationModel` = `disabled` (default) | `enabled`; a disabled project, and any library project on the same SDK (client packages, shared schema libraries), is a plain build with no manifest, no generated code and no diagnostics, cannot be the target of a `CohesionResourceReference` (**COHSDK001**: "`Example.AppA.Database` has `CohesionApplicationModel` disabled; set it to `enabled` to reference it"), and can still be launched opaquely by a gateway with `AddExecutable(path, …)` (probe/ready-marker only). *Supersedes, named:* image ownership moves from the framework `.Application` to the customer's project — DESIGN v2.1 §7.1/§9.3/§10/§13, `DatabaseResource.Artifact` (becomes manifest-driven), #906's "re-homed" criterion, platforms rule 3 wording, `PLATFORMS_PROGRAM_PLAN:90` are amended together; **T2 — Gateway project (revised with D15).** One `Sdk.Gateway` executable = one `IApplicationModel` = one deployment unit = one namespace, with identity **declared**: `CohesionApplicationName` (RFC 1123, validated at `Build()`) is generated into `Gateway.CreateBuilder(string[] args)` ⇒ `Application.CreateBuilder(ApplicationName.Parse("appa"), args)` (new overload; `IApplicationBuilder.UseName` remains) and stamped as `[assembly: CohesionApplication("appa")]` — **metadata for tooling only, never read at run time** (no custom-attribute reflection on the entry assembly; zero reflection holds); the entry-assembly fallback (`ApplicationBuilder.ResolveName`) survives only in Local as a slug (every example gateway name is dotted and would throw in `ResolveNamespaceName` today). A gateway project is **`Program.cs` only** (R4): no `Gateway.cs`, no `Gateway.Describe(IApplicationBuilder)`, no generated `Gateway.CreateModel(args)` — the whole model is inline in `Program.cs` (§4.3) — and `Sdk.Gateway` projects always have `CohesionApplicationModel` enabled, because a gateway is itself a resource with a manifest and a control plane. The single-cluster "shared gateway" is a root `Example.Gateway` hosting the area gateways' models as an `IApplicationSet` — **one gateway instance over N models/N namespaces** (one client, one informer, one registry, state keyed by (namespace, ResourceId)), the one sanctioned exception to the identity rule, living in `cohesion-system` in-cluster; **the application set composes through control planes** (R4): the root references each area gateway project with `CohesionResourceReference`, `Sdk.Gateway` generates `Applications.<Name>` for each, and `set.AddApplication(Applications.Platform)` obtains that gateway's model at start through the gateway's own control plane — invoking the referenced executable with `--mode describe` (which emits the model document) locally, or reading its exported model in-cluster — then reconciles every model in one instance; no name is ever listed twice. **One owner per namespace:** every namespace/process-set carries the owning gateway identity — Kubernetes namespace annotation `cohesion.io/owner=<application>@<gateway-identity>` with the field manager = that identity; locally `.cohesion/<app>/owner` + pid file — and a gateway refuses to reconcile a namespace annotated with a different owner (actionable error) unless `--adopt`. In the single-cluster shape the root `IApplicationSet` gateway is the **sole production owner**; per-area gateways run alone only in Development (their own kind cluster or an `--adopt`ed namespace). **T7a — Declarative commands across references (owner direction 2026-09-05).** A descriptor returned by `Add<Area>*()` or `RemoteReference(...)` is typed by the target's kind (`IRezolvrResourceDescriptor`, `IIdentityHubResourceDescriptor`, …), and `<Area>.ApplicationModel` ships **command verbs** on it as `extension(...)` members — `dns.AddARecord(name, endpoint)`, `identity.AddAudience(name)`, `identity.AddClient(name, configure)`, `config.AddNamespace(name, seed)`, `secrets.IssueCertificate(name, subject)`, `database.AddDatabase(name)`. A command is a **declaration in the claiming application's desired state** (`IResourceCommand`: deterministic id from owner + target + kind + key, source-generated payload), not a call: `Build()` validates it against the command kinds the target's manifest accepts — the kinds its area's default control plane serves; the gateway applies pending commands **after the target reaches `Running`** and before dependents start, **delivered to the target's default control plane** (the one its `<Area>.ApplicationModel` delivers and the opt-in's `ResourceControlPlane.g.cs` registers — Web on `/cohesion/v1/*` of its `http` endpoint, Database on its `admin` endpoint, declared in the manifest as `controlPlane`; authenticated by the bootstrap credential, §5) — locally through the `<Area>.Client` command client against that control plane's observed endpoint, remotely through the peer gateway's control plane (`PUT /cohesion/v1/resources/{name}/commands/{id}`), which forwards to the target's default control plane, and directly inside an application set; observed state records `Applied`/`Rejected` (a rejection blocks the claiming resource's dependents with the provider's message); every command is stamped `owner=<application>`, removed by that owner's `--mode teardown`, and a conflicting key from a different owner is refused. `IApplicationBuilder.Environment` (the `IApplicationEnvironment` the model already carries) makes commands environment-conditional in code. Same-application commands need no grant; a remote provider accepts only the command kinds named in the peer's trust grant (O25). Consequence for the taxonomy: Identity no longer lists zones — each zone claims its own audience and clients; Platform seeds only shared configuration — each zone claims its namespace; a zone may register a development DNS record with Networking. This does not replace what a resource declares about *itself* in its own `Program.cs` (its schema, its zones, its flows): that is what a resource is; commands are what a resource wants from another.

## 4. The customer DX, end to end

### 4.1 Org repo root

`global.json` pins the .NET SDK version and every Cohesion SDK used in the repo — 19 Cohesion SDK pins today + `Sdk.Gateway` = 20 Cohesion SDK pins, plus the .NET SDK version; every Cohesion pin is `10.0.1-preview.3` (cohesion's version never sorts below any version present on a feed — T4); written by the template; COHSDK002 keeps them agreeing. `nuget.config` carries **no credentials, ever**: `nuget.org` (pattern `Assimalign.Cohesion.*`) plus the org's own feed (pattern `Example.*`); the staging feed is added per developer with `dotnet nuget add source … -u USER -p (gh auth token)` during the staging window only (before the nuget.org promotion at the `preview` gate, items 2–26). Hygiene is a control, not a one-off: `.github/workflows/credential-guard.yml` — the same guard the cohesion, cohesion-platforms and cohesion-examples repos run — fails CI on `packageSourceCredentials`, `ClearTextPassword` or a `ghp_`/`github_pat_` token in any tracked file, and the template's `.gitignore` carries `.cohesion/` and `parameters.json` (the gateway's local mount materializations and parameter store: 0600 on POSIX; DataProtection-encrypted on Windows). `Directory.Build.props` carries identity only (`CohesionOrganization=example` → image prefix; `CohesionContainerRegistry=ghcr.io/example`, empty = archive on disk; `VersionPrefix=1.4.0`); the SDKs set `OutputType`, TFM, preview features and `ImplicitUsings` themselves. A per-area `Directory.Build.props` (`Zones/AppA/`) sets `<CohesionApplication>appa</CohesionApplication>` once for every resource in the folder. Orchestration itself is opt-in **per project**, not per folder: each resource's csproj declares `<CohesionApplicationModel>enabled</CohesionApplicationModel>` to get a manifest, `Resource.g.cs` and its area's default control plane (§4.2.3; the landing-zone templates write it into every resource they scaffold, the single-resource templates leave it disabled — O26). Every template writes `CohesionApplication` explicitly (the `cohesion-app` template writes `acme` at the repo root), so the derivation rule — exactly two name segments → the first, lowercased/kebab (`Acme.Api` → `acme`); three or more → the second (`Example.AppA.Api` → `appa`) — is only a fallback, and `Build()` fails an application that realizes zero resources ("every reference crossed an application boundary; declare `CohesionApplication` or reference a resource of `appa`").

**4.2.1 `Example.AppA.Database` — an executable whose schema is C#:**

`Program.cs` (top-level statements — the only code file the SDK expects, exactly as for any .NET executable):

```csharp
DatabaseApplicationBuilder builder = DatabaseApplication.CreateBuilder(args);         // an ordinary builder; honors the ambient ResourceContext and the registered control plane because the opt-in generated them
SqlDatabaseEngine engine = builder.AddSqlDatabase(o =>
{
    o.RootPath   = Resource.Mounts.Data;                                                // Resource.g.cs: typed accessors over ResourceRuntime.Current (COHESION_* out-of-process; set per invocation in-process)
    o.Durability = Resource.Settings.DatabaseDurability.Get<StorageCommitDurability>();
});

builder.AddDatabase(engine, "orders", database =>                                     // the schema is code
{
    database.Type<Money>(type => type.Decimal(18, 2));                                  // custom type
    database.Table<Order>(table => { table.Key(o => o.Id); table.Index(o => o.CustomerId); });
    database.Table<OrderLine>(table => { table.Key(l => l.Id); table.References<Order>(l => l.OrderId); });
    database.Function("order_total", (long orderId) => Sql.Sum<OrderLine>(l => l.Quantity * l.UnitPrice, l => l.OrderId == orderId));
    database.Trigger<Order>(TriggerEvent.AfterInsert, (transaction, row) => transaction.Audit("order.placed", row.Id));
    database.Principal("appa-api", principal => principal.Grant(Permission.ReadWrite, "Orders", "OrderLines"));   // database-scoped identity
});

builder.AddSqlServer(engine, server => server.Listen(Resource.Endpoints.Db));
await builder.Build().RunAsync();                                                       // provisioning runs before the server accepts; the `admin` control plane is started by the opt-in, never by a verb

record Order(long Id, long CustomerId, Money Total);                                    // the types the schema is built from follow the statements
record OrderLine(long Id, long OrderId, int Quantity, Money UnitPrice);
readonly record struct Money(decimal Amount);
```

The csproj carries the opt-in and only what the gateway must know; everything the database *is* — tables, indexes, constraints, custom types, functions, triggers, principals — is C# through the Database builder in `Program.cs`, and schema compile/migrations (#857–#859) operate on that model. There is no `AddAdminEndpoint` in user code: the `admin` endpoint is the Database default control plane, wired by the opt-in (§4.2.3). **The Database builder API shown is illustrative: the Database area owns it, exactly as IdentityHub owns its user-flow pipeline, Rezolvr its zone API and SecretStore its policy API. This document prescribes none of them (R3).** With the opt-in enabled the same project is still the two-person-company database: one executable, in-process-capable, deployable as-is. Set it to `disabled` and it is a plain .NET database executable — no manifest, no `Resource.*`, no diagnostics — that no gateway can reference (COHSDK001) but that any gateway can still launch opaquely with `AddExecutable(path, …)`.

`Certificate="tls"` names the mount that carries the leaf, and its provenance is fixed: `certs/appa-api` is issued by AppA's own SecretStore on first resolution of a `Certificate=` mount, from the intermediate CA the Platform SecretStore issued to that store at first deploy through the trust-grant channel (§7); without a Platform application the per-app store self-seeds its own root CA (self-signed, development trust) or `parameter:` supplies the certificate, and production public endpoints may use `Certificate="public"` (ACME/public CA, a later item). Both manifest-package references cross an application boundary, so the gateway generates `Externals.PlatformConfigurationStore` and `Externals.IdentityHub` (§4.3, §7) — never an `Add*` verb — and the resource reads them exactly as it reads a realized dependency (`Resource.References.PlatformConfigurationStore.Api`, `Resource.References.IdentityHub.Https`); the non-optional crossing blocks start only until it resolves, bounded by `ReadinessBudget`. Every `CohesionResourceReference` target must itself be `enabled` — the reference identifies the target's manifest at build time and its exposed control plane at run time (§4.2.3).

`Program.cs` (customer-authored, top-level statements; nothing else is generated into the entry path):

```csharp
WebApplicationBuilder builder = WebApplication.CreateBuilder(args);                   // a plain .NET exe; endpoints, mounts, settings, environment, signals and the bootstrap credential arrive through ResourceRuntime.Current
ISqlClient orders = SqlClient.Create(new SqlClientOptions
{
    Settings          = DatabaseConnectionSettings.For(Resource.References.AppADatabase.Db.Url, database: "orders", principal: Resource.Name),
    ConnectionFactory = Resource.References.AppADatabase.Db.ConnectionFactory(),       // TCP; in-process resolves to loopback too

if (Resource.References.IdentityHub.Https.TryGetUrl(out Uri? authority))               // Optional external: absent when unresolved
    builder.AddAuthentication().AddJwtBearer(o => o.Authority = authority);

```

`WebApplication.CreateBuilder(args)` composes `appsettings.json` → `appsettings.{Environment}.json` → `COHESION_CONFIG__*` → `args` (with `appsettings.Local.json` for developer machines and `appsettings.Development.json` for deployable Development) and, because the opt-in generated `ResourceControlPlane.g.cs`, honors the ambient `ResourceContext` (`ResourceRuntime.Current`) and the registered Web default control plane: `WebApplication.Build()` maps `/cohesion/v1/*` on the `http` endpoint — readiness/liveness/health aggregation over the resource's `AddHealthCheck`s and `IHealthContributor`s, observed endpoints, graceful stop, and the Web command kinds — together with `Web.Health`'s `/healthz|/readyz|/livez`, **first**, ahead of every user middleware, so those routes are terminal before `UseRouting`. With the opt-in disabled the same `Program.cs` is a plain Web application and `Build()` maps nothing of its own. Typed settings opt-in via `CohesionAppSettingsClass`.

#### 4.2.3 The manifest-generation contract (D2 revised; D3 withdrawn by R4)

**Opt-in, one MSBuild task, no Roslyn generator.** `CohesionApplicationModel` = `disabled` (default) | `enabled`, declared per project in the csproj. There is always a user `Main` — `Program.cs` top-level statements (or an explicit `Main`) — so nothing needs to see the compilation: the MSBuild task owns everything, reference-free, and the Roslyn generator `Assimalign.Cohesion.SourceGeneration.Resource` and its `CohesionFrameworkAnalyzer` entry are withdrawn (R4). Entry-point modes are gone with it: no `CohesionResourceEntryPoint`, no `Resource.Compose` seam, no generated `Main`, `CreateHost` or `Program.g.cs`, no `WarningsAsErrors CS7022`, no COHSDK007.

**Disabled** — a plain exe. No manifest, no generated code, no diagnostics; the SDK adds nothing to the build beyond the area framework. It cannot be referenced with `CohesionResourceReference`: **COHSDK001** (new meaning) — "`Example.AppA.Database` has `CohesionApplicationModel` disabled; set it to `enabled` to reference it", raised by the referencing project's build. A gateway can still launch it opaquely with `AddExecutable(path, …)` (probe/ready-marker only, §4.3 binding table) — it is a third-party executable as far as orchestration is concerned.

**Enabled** — `Sdk.<Area>` runs `CohesionCreateResourceManifest` (base SDK task; `BeforeTargets=CoreCompile`; no compile) and generates three generated outputs (plus the design-time target `CohesionGetManifest`), listed under **Outputs** below: `obj/…/cohesion/resource.json` (the manifest, from the orchestration-facing csproj items plus `controlPlane`), `Resource.g.cs` (constants and typed accessors over the ambient context) and `ResourceControlPlane.g.cs` (registration with the area's default control plane). `Sdk.Gateway` projects are always `enabled` — a gateway is itself a resource with a manifest and a control plane (the Composite already required this).

**The ambient context.** Everything `Resource.g.cs` exposes is backed by an ambient `ResourceContext` — `ResourceRuntime.Current` — populated from the `COHESION_*` environment out-of-process (with no gateway, `COHESION_GATEWAY` unset, endpoint accessors fall back to the manifest's `DevPort` so standalone `dotnet run` keeps stable URLs) and set **per invocation** by the in-process gateway (§6). The area builder (`WebApplication.CreateBuilder(args)`, `DatabaseApplication.CreateBuilder(args)`, …) honors the ambient context and the registered control plane when the opt-in generated them, and behaves as a plain application otherwise. Recommended mechanism — an SDK/area implementation detail under the R3 caveat, not a contract: a `[ModuleInitializer]` registration keyed by assembly plus an `AsyncLocal` ambient context scoped per invocation, so N resources in one process stay isolated; this replaces the withdrawn `ResourceHostContext.StartupHooks`. Tests set a scoped context with `ResourceRuntime.CreateScope(...)` and drive the same `Program` through `WebApplicationTestFactory.FromProgram<Program>()` (Database equivalent in `Database.Testing`; T27).

**The area-owned default control plane.** `ResourceControlPlane.g.cs` registers this assembly's resource with the **area's default control plane**, delivered by `<Area>.ApplicationModel` (a package the opt-in brings in; a disabled project never references it, so rule (1) of §2 and O2 hold): readiness/liveness/health aggregation over `builder.AddHealthCheck(name, check)` and every `IHealthContributor` (`Assimalign.Cohesion.Hosting.Health`, Core-only), observed endpoints, graceful stop, and the area's command kinds (the T7a declarative commands land here). Every resource of one type exposes the same default control plane — that is why each resource *type* owns its `<Area>.ApplicationModel`. Web: `/cohesion/v1/*` on the `http` endpoint; Database: the `admin` endpoint — `DatabaseAdminEndpointService : BackgroundService` in `Database.Hosting` hosting a private `WebApplication` (`Web.Hosting`) with `Web.Health` mapped over the process's `IHealthContributor`s (T19, O23) — started by the registered control plane, never by a user verb (`AddAdminEndpoint` is withdrawn from user code); other kinds per their `<Area>.ApplicationModel`. The manifest declares it (`controlPlane: { endpoint, path }`), the bootstrap credential authenticates it (§5), the gateway probes readiness there when no explicit probe is declared, and declared commands are delivered there.

**`CohesionResourceReference` identifies the manifest and the exposed control plane.** Build time: the target's manifest — typed constants (`Resource.References.<Res>.<Ep>`), inferred edges, application-boundary detection and the closure walk — unchanged. Run time: the target's control plane — readiness/health, observed endpoints, and the command kinds it accepts; gateways bind to it (through the peer gateway's control plane when the target is remote, R1) and apply declared commands (R2) through it.

**Composable.** `artifact.composable` in the manifest = "`CohesionApplicationModel` enabled **and** the area kind is composable" (`Sdk.LoadBalancer`/`NatGateway`/`VpnGateway` default it to false — thread-per-core data planes); there is no entry-point axis. In-process realizability stays a **compile-time** fact of the gateway: `CohesionCreateResourceVerbs` runs `AfterTargets=ResolveProjectReferences` (referenced resource projects are already built) and reads `artifact.composable` from each `resource.json`, so the generated in-process binding — the resource's entry point (`Program.Main`) invoked on its own thread under a per-invocation ambient `ResourceContext`, the `IHost` its area builder returns adopted by `ProcessHost` (§6) — exists only for project-referenced, composable resources; a manifest-package reference has no symbol, so `--gateway inprocess` on it is a `Build()` failure naming the resource; manifest-package references stay out-of-process only; a plain (disabled) exe is never nested. Templates emit `Program.cs` for every kind: the landing-zone templates write `CohesionApplicationModel=enabled` into every resource they scaffold (they are all referenced), the single-resource templates (`cohesion-web`, `cohesion-database`, …) leave it disabled with a comment showing the opt-in (O26).

**Inputs** (order `Sdk.<Area>.props` → csproj → `Directory.Build.props`; unknown metadata fails the build; an `ItemDefinitionGroup` gives IntelliSense): `CohesionResourceKind` (SDK; selects the `<Area>.ApplicationModel` type and, with it, its planner and the default control plane) · `CohesionApplicationModel` (`disabled|enabled`; The shape is the same generic `cohesion/resource/v1` for every resource of an area (R5): `endpoints[].protocol` is `tcp` unless `udp`; a `Volume` mount additionally carries `"size": "10Gi"` (`CohesionMount Size=`; the area default — e.g. the Database `data` mount; this Web sample has none); `properties` keys stay kind-prefixed (`web.kind`). The manifest never carries services, claims, ingress, sidecars, scheduling, storage classes, platform objects or package names — those are decided by the area's planner as a `ResourcePlan` at `Build()` (§5, Realization plan row) and realized by the selected platform's compiler.

2. `Resource.g.cs` (MSBuild task, written with the manifest) — one `public static partial class Resource` in the project's root namespace: `Name`, `Application`, `Kind` constants and typed accessors `Endpoints.<Ep>` (a `System.Uri`), `Mounts.<M>` (the materialized path), `Settings.<Section><Key>` (the configured value over `COHESION_CONFIG__…`, defaulted from the manifest — `Get<T>()`), `References.<Res>.<Ep>` (each reference endpoint exposes `.Url` as a `System.Uri`, `.TryGetUrl(out Uri?)`, and `.ConnectionFactory()`), all backed by the ambient `ResourceContext` (`ResourceRuntime.Current`); plus `internal static readonly ResourceManifestDefaults Manifest`, the defaults the ambient context is seeded with (`DevPort`, setting defaults) when the `COHESION_*` environment carries no value. It never references the orchestration plane.

3. `ResourceControlPlane.g.cs` (MSBuild task, written with the manifest) — registers this assembly's resource with the area's default control plane delivered by `<Area>.ApplicationModel` (the `[ModuleInitializer]`-keyed-by-assembly registration above): health aggregation over `AddHealthCheck` and `IHealthContributor` (`DatabaseApplicationContext` implements it from `IDatabaseEngine.State` + `Workers`), observed endpoints, graceful stop, command kinds. Per-invocation ambient context ⇒ per-host isolation: N Web resources nested in one process (topologies 1/4′) each see only their own context and their own health checks (§6(c)). No file is generated into the entry path — `Program.cs` is the customer's.

The Database composition in §4.2.1 is the customer's own `Program.cs` (there is no SDK template — R3): `DatabaseApplication.CreateBuilder(args)` → `AddSqlDatabase` → `AddDatabase(engine, name, schema)` (tables, types, functions, triggers, principals in C#) → `AddSqlServer` → `Build().RunAsync()`. `AddDatabase` provisions before accept; it is a `Database.Hosting` verb on the concrete `DatabaseApplicationBuilder`, not a root verb. The `admin` endpoint is the Database default control plane, started by the control plane the opt-in registered rather than by a verb: an internal `DatabaseAdminEndpointService : BackgroundService` that hosts a private `WebApplication` (`Web.Hosting`) with `Web.Health` mapped over the process's `IHealthContributor`s — `Database.Hosting` takes `CohesionPrivateProjectReference`s on `Assimalign.Cohesion.Web.Hosting` and `Assimalign.Cohesion.Web.Health` (cross-area private references are the sanctioned `CohesionPrivateProjectReference`/`CohesionFrameworkPrivateAssembly` mechanism; COHRES001/002 constrain same-area references only), `App.Database` gains the private closure (`Web.Hosting`, `Web.Health`, `Web.Routing`, `Http`, `Http.Connections`, `Connections.Tcp`, `Http.RequestLimits` — whatever the pack validation reports missing; O23), and the Database root's private `Web` reference stays as-is. Verb order is readability only: `DatabaseApplication` starts additional services before servers (`Database.Hosting`), so provisioning precedes accept regardless of the order the verbs are called. Schema compile (#859) and migrations (#857–#858) operate on the C# schema model `AddDatabase` builds.

4. `CohesionGetManifest` — design-time target in the **base SDK** (`DependsOnTargets=CohesionCreateResourceManifest` only: evaluation + manifest task, no compile — `composable` is already in `resource.json` from the opt-in and the kind; a disabled project yields no manifest and the walk reports it as COHSDK001; `SkipNonexistentTargets=true` for foreign projects) returning manifest path, `$(TargetPath)`, apphost path and the transitive closure with each hop's `application`.

**Container image** — `dotnet publish -c Release -t:CohesionPublishImage`: `EnableSdkContainerSupport=true`, **`ContainerImageFormat=OCI`** (the SDK's single-RID path passes the format through unchanged and MCR bases are Docker schema2 — without this the archive is a docker-save tar whose digest matches nothing after any load), `RuntimeIdentifier=linux-x64` (`linux-musl-x64` opt-in), `ContainerRepository`, `ContainerImageTags=$(Version)`, base `runtime-deps:10.0`, `PublishAot`/`SelfContained` per T12, `ContainerPort` per endpoint, labels `org.cohesion.resource|kind|manifest`; runs the .NET SDK's `PublishContainer`. **Exactly one `CreateNewImage` invocation produces the shipped digest**: registry sink (`ContainerRegistry`) when `CohesionContainerPush=true`, else the OCI-layout archive — never both (a second publish is not byte-identical). `image.json` is written from `GeneratedContainerDigest`; `VerifyImageDigestTask` asserts `index.json` (or the registry's returned digest) equals it: `{ "schema": "cohesion/image/v1", "resource", "repository": "example/appa-api", "registry" (late-bound per target, DESIGN §14.1 resolved), "tag", "digest": "sha256:…", "platform", "aot", "baseImage", "archive" (present only when published in this build) }`. Pull references are always `repository@digest`. Archives never ship inside NuGet by default (`CohesionPackImageArchive=true` = air-gapped opt-in). `kind load image-archive` preserves OCI digests (pods use `repo@digest`); the Docker daemon cannot resolve `@sha256` for loaded images, so the Docker gateway verifies the archive digest and runs by image ID; skopeo/crane/oras push (`CohesionContainerPushTool`) is an opt-in that preserves digests. "No-registry" tiers are therefore **source-present** tiers: a NuGet-only consumer without a registry has no image bits, and the design says so.

**Manifest package** — `dotnet pack` (`CohesionPackManifest`) produces `Example.AppA.Api.Manifest.1.4.0.nupkg` only: `IncludeBuildOutput=false`, `SuppressDependenciesWhenPacking=true`, `<FrameworkReference Update="Assimalign.Cohesion.App*" PrivateAssets="all" />` (the SDK's implicit framework reference never reaches the nuspec); contents `cohesion/resource.json`, `cohesion/image.json`, `buildTransitive/<Id>.props` (contributes a `CohesionResourceManifest` item), `README.md`. No assemblies, no dependencies. Tag-without-digest is COHSDK004 — a warning, an error only under `CohesionImageRequired=true`. `buildTransitive` props import for `PackageReference` only; the same-repo path uses `CohesionGetManifest`, so both routes yield identical items.

    <CohesionApplicationName>appa</CohesionApplicationName>                    <!-- declared identity → namespace; generated Gateway.CreateBuilder(args); [assembly: CohesionApplication] is tooling metadata only -->

`Sdk.Gateway` turns project references into `<ProjectReference ReferenceOutputAssembly="false" OutputItemType="CohesionResourceManifest" />` (built, never referenced) — plus a real runtime reference **only** under `CohesionGatewayInProcess=true` (with `ValidateExecutableReferencesMatchSelfContained=false` and an explicit `<FrameworkReference>` per referenced area, since `ReferenceOutputAssembly=false` references do not flow `TransitiveFrameworkReference`); every referenced project must have `CohesionApplicationModel=enabled` — a disabled project generates no manifest and cannot be referenced (**COHSDK001**: "`Example.AppA.Database` has `CohesionApplicationModel` disabled; set it to `enabled` to reference it"), and a gateway can still launch such a plain executable opaquely with `AddExecutable(path, …)` (probe/ready-marker only); package references self-register via `buildTransitive`; the orchestration `PackageReference`s are injected (T11), plus the matching `<Area>.Client` package for every `<resource>:<key>` mount source whose target kind is SecretStore/ConfigurationStore (kind → client map in `Sdk.Gateway.props`; here `appa-secretstore:certs/appa-api` injects `Assimalign.Cohesion.SecretStore.Client`); then `CohesionCreateResourceVerbs` (`AfterTargets=ResolveProjectReferences` — the referenced resource projects are already built, and it reads each manifest's `artifact.composable` (opt-in enabled **and** a composable area kind; there is no entry-point axis) and `controlPlane`, never the compilation) emits `Resources.g.cs`: `[assembly: CohesionApplication("appa")]` (tooling metadata — never read at run time); `public static partial class Gateway { public static IApplicationBuilder CreateBuilder(string[] args) => Application.CreateBuilder(ApplicationName.Parse("appa"), args); }` (the name is compiled in — no attribute reflection; `IApplicationBuilder.UseName` remains); `extension(IApplicationBuilder)` verbs `AddAppADatabase(Action<DatabaseResourceOptions>?) => builder.AddDatabase(Manifests.AppADatabase, configure)` with an `.InProcess(…)` binding to the member's generated entry (`Program.Main` — the compiler's entry point for its top-level `Program.cs` — which `ProcessHost` invokes on its own thread under a per-invocation ambient `ResourceContext`, adopting the `IHost` the area builder returns, §6) only when in-process and `artifact.composable`, `AddAppAApi`, `AddAppASpa`, `AddAppASecretStore`, `AddAppAWorker` (from the manifest package — same application `appa`, other repo, image-only; never nested), `AddAllResources()`; `public static class Externals { public static readonly ExternalResourceDeclaration IdentityHub = new("identity-hub", application: "identity", endpoints: ["https"], optional: true, manifest: Manifests.IdentityHub); public static readonly ExternalResourceDeclaration PlatformConfigurationStore = new("platform-configurationstore", application: "platform", endpoints: ["api"], optional: false, manifest: Manifests.PlatformConfigurationStore); }` — every boundary crossing in the closure becomes a descriptor, never an `Add*` verb; for every referenced project that is itself an `Sdk.Gateway` project, `Applications.<Name>` — the application descriptor a root application set adds with `set.AddApplication(Applications.AppA)` to obtain that gateway's model through the gateway's own control plane (§4.5(b)); `Manifests.*` = `ResourceManifest.Parse("""…embedded…""")` via a source-generated STJ context. `Sdk.Gateway` also generates `UseGateway(args)` (and its `UseGateway(args, gateways => …)` overload) as a static switch over the `CohesionGatewayProvider` items (`Name`, `GatewayType`, `OptionsType`, `RequiresJit`) that the platform packages named in `<CohesionGateways>` contribute through their buildTransitive props — cohesion source never names a platform type, and injection is keyed on `<CohesionGateways>` only (R5). `Build()` then plans every resource — its area's planner from `<Area>.ApplicationModel`, else `GenericPlanner`; an informational line names the path per resource (`appa-database: Database planner → kubernetes compiler`), never a silent fallback — validates each `ResourcePlan` (`ResourcePlanValidator`) and asks the selected gateway `CanRealize(plan, out reason)` before any gather, so an unrealizable plan fails at `Build()` naming the resource and the gateway; `--mode render` prints the compiled platform objects for the selected gateway without contacting it (§4.4). Because `CohesionApplicationModel` is always enabled for a gateway, the same manifest task writes the gateway's own `resource.json` (a Composite's re-exports member endpoints, T15), and the `Gateway.ControlPlane` endpoint every gateway serves (§7) is the control plane a root application set or an outer gateway binds to.

`Program.cs` (federated Zones/AppA gateway) — the whole model, inline; a gateway is `Program.cs` only (R4):

```csharp
IApplicationBuilder builder = Gateway.CreateBuilder(args);       // generated: Application.CreateBuilder(ApplicationName.Parse("appa"), args); honors --environment, --gateway, --external, --realize, --mode
var secrets  = builder.AddAppASecretStore();
var identity = builder.RemoteReference(Externals.IdentityHub, remote => remote.Gateway("https://identity.example.com/cohesion")); // binds the generated external to the Identity gateway's control plane; --external / config re-bind it per environment
var config   = builder.RemoteReference(Externals.PlatformConfigurationStore, remote => remote.Gateway("https://platform.example.com/cohesion")); // the non-optional crossing (§4.2.2), bound to the Platform gateway's control plane
var worker   = builder.AddAppAWorker();                          // same application, other repo (manifest package): realized image-only; edges inferred from its manifest references
var database = builder.AddAppADatabase(o => o.Storage.Size = "20Gi"); // typed option over a manifest fact (default 10Gi from Sdk.Database); DependsOn(secrets) inferred from its manifest references
var api      = builder.AddAppAApi(o => o.Replicas = 2);          // DependsOn(database, secrets, Externals.IdentityHub, Externals.PlatformConfigurationStore) inferred; Replicas validated against maxReplicas at Build()
var spa      = builder.AddAppASpa().DependsOn(api);              // explicit edge: ordering only (additive over inferred)

// Declarative commands (T7a): what appa wants from resources it references — applied by this gateway once the
// target is Running (through Identity's / Platform's control plane when remote), owned by appa, removed on teardown.
identity.AddAudience("appa-api");
identity.AddClient("appa-spa", client => client.AuthorizationCode().RedirectUri(spa.Endpoints.Http.PublicUrl("/callback")));
config.AddNamespace("appa", seed: "Configuration/appa.json");
if (builder.Environment.IsLocal())
{
    var dns = builder.RemoteReference("networking-rezolvr", remote => remote.Gateway("https://networking.example.com/cohesion")); // manifest-less: no AppA resource references Rezolvr, so the closure generates no Externals.* for it
    dns.AddARecord("appa-dev", api.Endpoints.Https);                // a development record in the org's DNS; gone when this gateway tears down
}
builder.UseGateway(args, gateways => gateways.Kubernetes(k => k.StorageClass = "fast-ssd")); // platform-specific exceptions live ONLY here (rule 6, O29): the callback runs only when this gateway is selected; --gateway local|inprocess|docker|kubernetes; default COHESION_GATEWAY, then Development→local
await builder.Build().RunAsync();                                // --mode run | apply | teardown | bootstrap | describe | render; Build() plans every resource (area planner or GenericPlanner), validates, and asks the selected gateway CanRealize; fails on an undeclared name or on zero realized resources
```

Externals need no code to be *declared* — the closure declares `Externals.IdentityHub` and `Externals.PlatformConfigurationStore` — and are *bound* either in code, `builder.RemoteReference(Externals.<Name>, remote => remote.Gateway(url) | .Endpoint(name, url) | .File(path) | .Kubernetes(context, ns))`, when the location is stable, or per environment by `--external`/configuration (environment always overrides code); `builder.RemoteReference("legacy-erp", remote => remote.Endpoint("https", url))` declares a manifest-less external. Resolution follows §7. Gateway `appsettings.json` (`Cohesion:External:<name>:Endpoints:<ep>`, `Cohesion:Kubernetes:{Context,Registry}`, `Cohesion:Local:StateRoot`) is bound by the source-generated binder over the `Assimalign.Cohesion.Configuration` stack — the gateway executable is a composition root, the sanctioned place for that seam.

A `CohesionResourceReference` identifies two things. At build: the manifest — typed constants, inferred edges, application-boundary detection and the closure walk. At run time: the target's exposed **default control plane** — readiness/health, observed endpoints and the command kinds it accepts — which this gateway binds to (through the peer gateway's control plane when the target is remote, R1), probes for readiness when the manifest declares no explicit probe (§5), and delivers declared commands through (R2, T7a).

### 4.4 Running and publishing

| Command | What happens |
|---|---|
| `dotnet run` (Local) | Builds referenced resource projects (each an ordinary executable with `CohesionApplicationModel=enabled`); allocates a loopback port per endpoint and **persists it** in `.cohesion/appa/ports.json` (stable URLs across runs — Aspire launchSettings parity); writes `.cohesion/appa/owner` (the gateway identity) and a pid file per child; materializes mounts, resolved secrets and each resource's bootstrap credential (`COHESION_BOOTSTRAP_TOKEN_PATH`) under `.cohesion/appa/<resource>/` (0600 on POSIX; DataProtection-encrypted on Windows); launches apphosts in topological order with the contract env; begins probing on the ready line, gates on the declared probe (or, when none is declared, on readiness at the member's default control plane — §5); injects `COHESION_DEPENDENCY_*`; applies declared commands through each target's control plane once it is `Running` (T7a); tails `[name]`-prefixed output; Ctrl+C → stop event/SIGTERM → grace (`CohesionStopGraceSeconds=30`) → kill, reverse order. On restart the gateway re-attaches to still-running children by pid file (or stops orphans and relaunches per `--restart-orphans`) |
| `dotnet run -- --gateway inprocess` | One process: `ProcessHost` invokes each member's generated entry (`Program.Main` — the compiler's entry point for its top-level `Program.cs`) on its own thread under a per-invocation ambient `ResourceContext` (`ResourceRuntime.Current`) and adopts the `IHost` the area builder returns — started one at a time by the controller, gated on readiness; loopback ports, endpoints, mounts, references and the bootstrap credential travel on that context; requires `CohesionApplicationModel=enabled` on every member (a plain exe is never nested — `Build()` names it); identical customer code |
| `… --gateway docker` | `CohesionPublishImages` if stale (Development → self-contained JIT on any host); digest-verified archive load, run by image ID; network `appa`; compiled from the plan by `DockerPlanCompiler` (R5): one container per resource (name = resource ⇒ Docker DNS; a `DaemonSet` plan = one container), named volumes per claim, run-once tasks for Job plans; public ports; gateway-side probes via loopback-only host bindings; stop = `docker stop -t 30` |
| `… --gateway kubernetes --context cluster-04` | Ensures namespace `appa` annotated `cohesion.io/owner=appa@<gateway-identity>` (field manager = that identity; a namespace owned by a different identity is an actionable error unless `--adopt`); loads images (kind/daemon in Development, embedded registry or `CohesionContainerRegistry` otherwise); server-side-applies ConfigMap, Secret (bootstrap credential at `COHESION_BOOTSTRAP_TOKEN_PATH`, rotated on every reconcile, + resolved mount sources), and, compiled from each resource's `ResourcePlan` by `KubernetesPlanCompiler` (R5), per `plan.Workload.Kind` — carried verbatim from `lifecycle.workload` — a Deployment, a StatefulSet (the per-replica claim sized from `mounts[].size` + the headless governing Service the area planner declared — `Sdk.Database` by default, any `Volume`-mounted kind via `GenericPlanner` — whose name is the Service DNS dependents receive), a DaemonSet or a Job — digest-pinned; `replicas` validated against `maxReplicas` at `Build()`; readiness/liveness/startup 1:1; `terminationGracePeriodSeconds: 30` — plus Service (ClusterIP; LB/Ingress for `public`); one informer publishes `Running` + Service DNS; writes `cohesion-export`; reconcile loop; Ctrl+C stops the watch and **leaves workloads running**. On restart the gateway re-lists and **adopts** its owned objects (owner annotation + field manager) and resumes reconciliation |
| `--mode apply` / `teardown` / `bootstrap` / `describe` | apply reconciles and exits 0 (CI/GitOps); teardown deletes the namespace / stops processes in reverse; bootstrap emits ClusterRole/ClusterRoleBinding/ServiceAccount/`cohesion-system` Deployment manifests for in-cluster mode; describe emits the gateway's model document and exits — no reconcile, no realization — which is how a root application set obtains a referenced gateway's model locally (`Applications.<Name>`, §4.5(b); in-cluster it reads the gateway's exported model instead) |
| `… --mode render --gateway kubernetes` | Prints the compiled Kubernetes objects for every resource (planner → `KubernetesPlanCompiler`), no cluster contact — the `helm template` of Cohesion; `--gateway docker` / `local` render their compiled container / process objects the same way; a plan schema newer than the selected compiler supports is refused here exactly as at `Build()` |
| `dotnet publish -t:CohesionPublishApplication` (gateway) | Publishes every resource image, gathers `application.images.json`, publishes the gateway image (in-cluster Deployment in `cohesion-system`); a Composite = the "one container for the whole app" artifact |
| `dotnet pack` (resource) | Manifest package for other repos (`CohesionApplicationModel=enabled`; a disabled project produces no manifest to pack) |
| `cohesion new\|run\|publish\|deploy\|trust\|parameter\|login\|status` (CLI, later) | Thin wrappers; no new semantics (`trust add` = the federation grant, `trust issue --developer` = the developer pull-down token, `parameter set` = the local secret parameter store) |

Restart durability is the same rule on every gateway: state is rebuilt from observation — the Kubernetes gateway re-lists and adopts what it owns, the Local gateway re-attaches by pid file — and is never persisted as truth.

### 4.5 Canonical folder scaffolds

**(a) Single-repo small business** — `dotnet new cohesion-app -n Acme`: the root `Directory.Build.props` writes `<CohesionApplication>acme</CohesionApplication>` (templates always write it; the two-segment fallback — first segment, `Acme.Api` → `acme` — is only a fallback); `Acme.Api` (`Sdk.Web`, `Program.cs`, `CohesionApplicationModel=enabled`, references `Acme.Database`), `Acme.Database` (`Sdk.Database`, `Program.cs` defining its schema in C#, `CohesionApplicationModel=enabled`), `Acme.Gateway` (`Sdk.Gateway`, `Program.cs`, `CohesionApplicationName=acme`: `AddAllResources(); UseGateway(args)`; InProcess=true; Docker). The template writes `CohesionApplicationModel=enabled` into every resource it scaffolds because every one of them is referenced (O26). `dotnet run --project Acme.Gateway` = one process (both resources' generated entries invoked under per-invocation ambient `ResourceContext`s — the opt-in is what makes nesting possible); `--gateway docker` = two containers. `Build()` rejects an application that realizes zero resources ("every reference crossed an application boundary; declare `CohesionApplication` or reference a resource of `acme`"), so a missing or mis-derived application name can never produce an empty gateway silently. Topology 0: `Acme.Api` alone with `EmbeddedDatabase`, a file key ring and `<FrameworkReference Include="Assimalign.Cohesion.App.Database" />` — no gateway; the single-resource `cohesion-web` template leaves `CohesionApplicationModel` disabled (a plain executable, nothing generated) with a comment showing the opt-in.

**(b) Mono-repo, single cluster** — `examples/k8s/` corrected: `Gateway/Example.Gateway` (`Sdk.Gateway`, `IsApplicationSet`; hosts the area models; `cohesion-system` in-cluster; `--context cluster-01`); `Identity/` (`Directory.Build.props`: `CohesionApplication=identity`; `Example.Identity.IdentityHub`, `Example.Identity.Gateway`); `Networking/` (`Example.Networking.Rezolvr` ← "Dns", `Example.Networking.VpnGateway` ← "Exmaple", `Example.Networking.Gateway`); `Platform/` (`ConfigurationStore`, `SecretStore`, `LogSpace`, `Example.Platform.Gateway`); `Zones/AppA|AppB|AppC` (`appa|appb|appc`; flat siblings `Api`, `Spa`, `Database`, `SecretStore`, `Gateway`; nested gateway folder removed; AppC a real copy). Namespaces `identity`, `networking`, `platform`, `appa`, `appb`, `appc` (+ `cohesion-system`). Every resource the landing-zone template scaffolds is `Program.cs` plus a csproj carrying `CohesionApplicationModel=enabled` (they are all referenced — O26). Each area gateway is `Program.cs` only, holding its whole model inline (§4.3), and — as every `Sdk.Gateway` project — has `CohesionApplicationModel` enabled, so it is itself a resource with a manifest and a control plane. The root `Example.Gateway` references the area gateway projects with `CohesionResourceReference`, exactly as a Composite references members; `Sdk.Gateway` generates `Applications.<Name>` for each (`Applications.Identity`, `Applications.Networking`, `Applications.Platform`, `Applications.AppA`, `Applications.AppB`, `Applications.AppC`), and `set.AddApplication(Applications.Platform)` obtains that gateway's model at start through the gateway's own control plane — invoking the referenced executable with `--mode describe` (it emits the model document) locally, or reading its exported model in-cluster — then reconciles every model in one instance (one client, one informer, one registry, state keyed by (namespace, ResourceId)); no name is ever listed twice. **One owner per namespace:** the root `IApplicationSet` gateway is the sole production owner of every namespace it hosts (`cohesion.io/owner=<application>@<gateway-identity>`, field manager = that identity); a per-area gateway runs alone ("pull one area down") **only in Development** — against its own kind cluster or an `--adopt`ed namespace — never as a second reconciler of a production namespace. The README note states the nested shape is **rejected**: "folder nesting never expresses ownership; the nested `Example.AppB.Gateway/Example.AppB.*` and copy-pasted `AppC` trees are removed; per-area gateways were added for Identity/Networking/Platform".

**(c) Federated multi-cluster** — `examples/k8s-federated/`: identical tree minus `Gateway/`. Platform → cluster-03 / `platform` / `Example.Platform.Gateway` / deployed first, root of trust (its SecretStore issues each application's SecretStore an intermediate CA through the trust-grant channel; every application verifies peers against the `TrustedIssuers` list in its own SecretStore). ## 5. The runtime contract (gateway ⇄ resource)

One carrier out-of-process (env vars), one in-process (the ambient `ResourceContext` — `ResourceRuntime.Current`, set per invocation by the in-process gateway; out-of-process the same context is populated from the `COHESION_*` environment, so the typed accessors `Resource.g.cs` generates — `Resource.Endpoints.<Ep>`, `Resource.Mounts.<M>`, `Resource.Settings.<SectionKey>`, `Resource.References.<Res>.<Ep>` — read one context everywhere), identical keys. Endpoint values are `System.Uri`; Core's C# 14 `UriExtensions` block constructs and validates endpoint URIs and provides `ToEndpointString()` as the only writer form for `COHESION_*_URL`/`_PUBLIC_URL`: `scheme://host:port[/path]`, explicit port, percent-encoded path, no trailing slash for the root path, and no user information, query, or fragment. Socket APIs consume `Uri.IdnHost` by convention. Constants are `public const string` on `Assimalign.Cohesion.Core.ResourceEnvironment` (inlined per consumer ⇒ a **frozen wire contract**; a value change is breaking), with helpers `Endpoint(name, suffix)`, `Mount(name)`, `Dependency(resource, endpoint, suffix)` carrying the one canonicalization rule (uppercase, `[^A-Z0-9]`→`_`, ordinal). `AppEnvironment.Keys` goes public and `ApplicationEnvironment` delegates to it (its duplicated `"COHESION_ENVIRONMENT"` literal today proves a shared assembly alone does not stop drift); a guard fails any `"COHESION_"` literal outside `libraries/Core`; `docs/RUNTIME_CONTRACT.md` + a golden test pin the strings for non-.NET consumers. `COHESION_DATABASE_*` is removed outright (*why not aliases:* nothing shipped binds them).

## 7. Federation and "reference on the fly"

**Discovery surface = the application export**: `{ application, environment, version, trustKey (public JWK), resources: [{ name, kind, manifestHash, endpoints: [{ name, internal: "<svc>.<ns>.svc:port", public: "<url>|null" }] }] }` written to `.cohesion/<app>/export.json` (local), the `cohesion-export` ConfigMap (Kubernetes, by `Gateway.Kubernetes`), and the gateway **control plane** — `GET /cohesion/v1/application` (this document) and `GET /cohesion/v1/resources/{name}` (observed state and endpoints) served by **every** gateway from the new cohesion package `Assimalign.Cohesion.ApplicationModel.Gateway.ControlPlane` (`Http.Connections` + `Connections.Tcp` + `Web.Routing`, no `*.Hosting`, AOT; **v1, not v2**): Local on loopback (URL recorded in `.cohesion/<app>/control-plane.json`), Docker on the host, Kubernetes through the `cohesion-system` Service plus an Ingress/LB for cross-cluster — this is what `builder.RemoteReference(…, remote => remote.Gateway(url))` talks to. Never mount sources or secret values — an export contains no secrets by construction, so reading one discloses nothing a trust grant protects.

**Two control planes, two owners (R4).** The gateway control plane above is the *application's*. Each resource with `CohesionApplicationModel` enabled additionally exposes its area's **default control plane** — Web: `/cohesion/v1/*` on its `http` endpoint; Database: the `admin` endpoint; other kinds per their `<Area>.ApplicationModel` — declared in its manifest as `controlPlane: { endpoint, path }` and registered at run time by the generated `ResourceControlPlane.g.cs` (§4.2.3; §5 **Control plane** row): readiness/liveness/health aggregation (every `builder.AddHealthCheck(...)` the resource adds), observed endpoints, graceful stop and the command kinds the area accepts. Every resource of one kind exposes the same default control plane — that is why each resource type owns its `<Area>.ApplicationModel`. The resource's **own** gateway binds to it, authenticated by the bootstrap credential, probes readiness there when no explicit probe is declared, and delivers declared commands there; a remote gateway never addresses a peer's resource directly — everything it learns about, or asks of, that resource passes through the peer gateway's control plane, which is what `RemoteReference` binds to (R1). A disabled project has no control plane and no manifest, so it can never be a reference target (COHSDK001) — only an opaque `AddExecutable(path, …)` with a probe or ready marker. An application set (§4.5(b)) obtains each member gateway's model the same way, through that gateway's own control plane: locally by invoking the referenced executable with `--mode describe` (it emits the model document), in-cluster by reading its exported model. The model document carries each resource's `ResourcePlan` (`cohesion/plan/v1`, computed by that gateway's `Build()` from the manifest + typed options) beside its manifest, so an application set — and a federated peer bound by `RemoteReference` — compiles a member's resources with its own platform compiler without loading any `<Area>.ApplicationModel`; the plan is platform-neutral and carries no secrets, so the export's no-secrets guarantee holds.

**Resolution seam.** `IExternalResourceResolver` (ApplicationModel, Core-only). An external is an ordinary resource whose controller *is* its resolver: it runs inside the topological reconcile and publishes imported endpoints via `SetState(id, Running, observedEndpoints)` (manifestHash + referenced-endpoint check there → `Failed` with an actionable message); `Optional` unresolved → `Skipped`. No `ResourceLifecycle.Ready`; platforms rules 2/5/8 stay intact. Modes (code → configuration → imports): **Declared by the closure, bound in code or by environment.** `builder.RemoteReference(Externals.<Name>, remote => …)` (owner direction 2026-09-04) is the C# form: it returns a descriptor (so `DependsOn` chains and the node sits in the graph like any resource) and names where the remote resource lives; `RemoteReference("name", remote => remote.Endpoint(…))` declares a manifest-less external whose endpoints it must state itself. Binding forms, code → configuration → imports: (1) **Control plane** — `remote.Gateway(url)`: the peer gateway's `Gateway.ControlPlane` endpoint (export + observed state), authenticated per (6) — **v1**; (2) **Static** — `remote.Endpoint(name, url)`, `Cohesion:External:<name>:Endpoints:<ep>` or `--external name=<ep>=<url>` (base Gateway); (3) **File** — `remote.File(path)`: an export document on disk / a mounted ConfigMap (base); (4) **Kubernetes** — `remote.Kubernetes(context, namespace)` / `--external name=kubernetes:<context>/<namespace>` → `ImportFromKubernetes` in cohesion-platforms (API client; another cluster needs a kubeconfig context — the **operator** trust channel of (4) below, ordinary namespace RBAC, distinct from application trust); same cluster → Service DNS, laptop → public endpoint or a gateway-managed **port-forward** in Development. Environment always overrides code (`--external`/configuration re-bind a `RemoteReference` per environment); a generated external with neither a `RemoteReference` nor an environment binding resolves through imports or fails per its `Optional` flag. `Build()` fails when a `RemoteReference` names a generated external that does not exist (a typo against the closure — the closure declares every crossing); an unresolved non-optional external is `Failed` after `ReadinessBudget` (per-resource override), dependents `Blocked`, reverse teardown — never an indefinite wait.

**Declarative commands across references (T7a).** The second thing a reference gives you, after its endpoints: the right to *declare* what you need from it. Mechanics: (1) **Verbs** ship in `<Area>.ApplicationModel` as `extension(I<Area>ResourceDescriptor)` members and record an `IResourceCommand` on the descriptor; the command kinds a target accepts are those of its area's **default control plane** — identical for every resource of one kind — listed in the target manifest (`"commands": ["rezolvr.record", "identityhub.audience", …]`, written when `CohesionApplicationModel` is enabled and registered at run time by the generated `ResourceControlPlane.g.cs`), and `Build()` rejects the rest. (2) **Apply** is a step of the generic gateway algorithm: after `WaitForStateAsync(target, {Running, …})` and before any dependent reconciles, pending commands are applied idempotently, and they are always **delivered to the target resource's default control plane** — same application: the `<Area>.Client` command client against the `controlPlane` endpoint and path the target's manifest declares (loopback in-process and locally, container DNS, Service DNS); remote: `PUT /cohesion/v1/resources/{name}/commands/{id}` on the peer gateway's control plane, which the peer gateway delivers to its resource's default control plane with the same client and answers with the command's observed status; application set: direct — the set's one instance delivers to the target's default control plane itself. (3) **Ownership**: every command carries `owner=<application>`; `GET …/commands` lists them with owners; the owner's `--mode teardown` (or removing the declaration and re-applying) deletes them; a conflicting key from another owner is refused with an actionable message, never overwritten. (4) **Failure**: `Rejected` blocks the claiming resource's dependents (`Blocked`, provider message), bounded by `ReadinessBudget`; `Optional` commands never block. (5) **Authorization**: same-application commands need no grant; a remote provider accepts only the command kinds the peer's trust grant names (`cohesion trust add appa --against https://identity.example.com/cohesion --allow identityhub.audience,identityhub.client`) — O25. (6) **Environment**: `IApplicationBuilder.Environment` is the model's `IApplicationEnvironment`, so a command can be declared only in Development, exactly as a resource can.

**Pulling an area down.** `git clone`, `cd Zones/AppA/Example.AppA.Gateway`, `dotnet run -- --external identity-hub=https=https://identity.example.com --external platform-configurationstore=api=https://config.example.com` (or `--external identity-hub=kubernetes:cluster-01/identity`, the operator channel). `Resource.References.IdentityHub.Https` is the same typed accessor as in production (`.Url`/`.TryGetUrl` read the ambient `ResourceContext`, populated from `COHESION_*` out-of-process). `--realize identity-hub` flips the crossing back to local and is **transitive**: it realizes `identity-hub` *and its same-application transitive closure* — from source when the Identity tree is present, otherwise from the manifest package's embedded closure (image-only, realized as a container via the Docker package per the §4.3 binding table; a realized member whose `<Area>.ApplicationModel` is not loaded is planned by `GenericPlanner` — a `Build()` warning names the kind); IdentityHub's own externals (`platform-secretstore`) stay external; realized-external resources keep their own `COHESION_APPLICATION` (`identity`) for naming but run in the current gateway's process set; their mount sources resolve through the current gateway's resolver (a `parameter:` left unbound is an error naming it); `--realize` is Development-only, honored by the Local/InProcess/Docker gateways and never by a Kubernetes reconcile. Remote credentials: until IdentityHub ships, an operator runs `cohesion trust issue --developer <name>` against the peer application, which mints a short-lived ES256 developer token (aud `cohesion-export`, exp ≤ 8 h, jti) that the developer's gateway presents to the peer's export endpoint — read-only; revocation = rotating the issuing trust key; after IdentityHub, `cohesion login` obtains the same token through the OIDC device flow.

**Identity (cluster-01) consumed by Zones (cluster-04).** `Example.AppA.Api` references `Example.Identity.IdentityHub.Manifest`; the Zones gateway's generated `Externals.IdentityHub` binds to Identity's public `https` endpoint (LB/Ingress, `identity.example.com`, TLS from the org CA or a public CA). Zones' import of Identity's export authenticates with a Zones-minted token that Identity verifies against the grant registered **on Identity** (`cohesion trust add appa --from <appa export>`, run on Identity — the verifier holds the grant, per (4)). End users: OIDC. Services: client credentials registered in IdentityHub, secret in AppA's SecretStore (`<resource>:<key>` mount).

**Security and trust bootstrap (D10 revised — two keys; one trust grant per peer, held by the verifier; operator trust is a separate channel):** (1) **Gateway trust key** — ECDsa P-256 generated at first deploy; private half persisted platform-natively (`Secret` in `cohesion-system` / local file), encrypted at rest with `Security.DataProtection` over a file key ring (AES-GCM = at-rest only, never the signer); public half published as `COHESION_APPLICATION_TRUST_KEY` and in the export. Distinct from the #806/#808 service rings. (2) **Bootstrap credentials = ES256 JWTs** (aud = resource name, exp ≤ 24 h, jti) minted with `JsonWebTokenWriter` (new; `ECDsa.SignData` is AOT-safe) and verified with the ECDSA verifier — both in `IdentityModel.Token.JsonWebToken` (item 25b; `Web.Authentication.Bearer` keeps its adapter). Delivery is the §5 **Bootstrap credential** row: `COHESION_BOOTSTRAP_TOKEN_PATH` names a file (0600 on POSIX; DataProtection-encrypted on Windows; tmpfs on Docker; a Secret volume on Kubernetes) rotated by the gateway on every reconcile; in-process it is a value on the ambient `ResourceContext` (`ResourceRuntime.Current`), set per invocation. No resource holds material that can mint. (3) **First deploy and certificate provenance:** Platform gateway (`--mode apply`) generates its trust key; Platform SecretStore starts, receives its bootstrap credential and **self-seeds the org root CA** when it holds none (no gateway→store write at day 0); Identity second (`platform-secretstore` for signing keys); Zones last. Nothing precedes the Platform gateway but kubeconfig and registry credentials. Every other application's SecretStore holds an **intermediate CA** issued by the Platform SecretStore at that application's first deploy through the trust-grant channel of (4): `cohesion trust add platform` on the application, then an enrollment request signed with the application's gateway trust key, which the Platform store verifies against its own `TrustedIssuers` and answers with the intermediate. Leaf certificates (`certs/appa-api`, the `tls` mount of §4.2.2) are issued by the per-application store on first resolution of a `Certificate=` mount. Without Platform (the §8 scale-down) the per-application SecretStore self-seeds its own root CA (self-signed, development trust) or `parameter:` supplies certificates; production public endpoints may declare `Certificate="public"` (ACME/public CA, a later item). (4) **Cross-application trust is explicit and per-application — one grant per peer, held by the verifier:** every application verifies with the `TrustedIssuers` list in **its own** SecretStore (the Platform SecretStore is the trust root only for the Platform application). `cohesion trust add <peer> --from <export-url|file>` registers the *peer* gateway's public key in the *verifying* application's SecretStore as a signed, persisted trust grant: Identity registers Zones' key, so a Zones-minted credential verifies at Identity's export endpoint with no ring export. Each gateway loads its own `TrustedIssuers` JWK set at start and hands it to its export endpoint and importers. Replaces v3's undeliverable "no out-of-band tooling" claim for federation. **Two channels, not one:** application trust is the grant above; `ImportFromKubernetes` over a kubeconfig context is an *operator* channel (the Development/operator path, ordinary namespace RBAC on the peer namespace) — because exports carry no secrets, ConfigMap readability needs nothing beyond that RBAC. (5) **Mount-source resolution** is gateway-side: `<resource>:<key>` fetched over the thin protocol client (`SecretStore.Client`/`ConfigurationStore.Client`, item 25a — the O13 deviation, narrow: gateways may reference `<Area>.Client`, never `*.Hosting`) with the gateway's own bootstrap credential; `Sdk.Gateway` injects the matching `<Area>.Client` `PackageReference` for every mount source `<resource>:<key>` whose target kind is SecretStore/ConfigurationStore (kind → client map in `Sdk.Gateway.props`); `parameter:<name>` bound from `.cohesion/<app>/parameters.json` (git-ignored — the templates' `.gitignore` carries `.cohesion/` and `parameters.json`; `cohesion parameter set`; 0600 on POSIX, DataProtection-encrypted on Windows like every secret materialized under `.cohesion/`) locally or an existing `Secret` on Kubernetes; unbound = `Build()`/`StartAsync` error naming it. Gateway→store reachability (Service DNS in-cluster; a gateway-only port-forward local-host) is a declared precondition. (6) Export/import auth: TLS with the org CA (root or per-application intermediate) + the importing gateway's ES256 token, verified by the exporting application against its own `TrustedIssuers` (v1); IdentityHub tokens (aud `cohesion-gateway`) after #64; mTLS optional; developer pull-down is read-only under the developer token of "Pulling an area down". (7) Rezolvr is not discovery; public names come from LB/Ingress + org DNS (which may be Rezolvr in its authoritative role). Trust grants are per verifying direction: enrolling an application with the Platform store is one grant on the Platform side (`cohesion trust add appa --from <appa export>`, run by the operator at the application's first deploy) and consuming Platform's export from the application is the grant on the application side — "one step per peer" means one per direction that needs to verify.

*Why not "resources pull secrets at start" (v3):* it made every `*.Hosting` orchestration-aware, added two clients to every runtime, had no in-process degradation, and contradicted the controller's own Secret emission; gateway-side resolution is what `DatabaseHostConfiguration.FromEnvironment()`, `WebApplicationBuilder`'s synchronous `Build()` and the platforms plan (L04.01.03.03) already assume.
